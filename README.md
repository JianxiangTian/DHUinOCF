# DHU in an Open Colloidal Flow: simulation and analysis code

Companion code for **“Nonlocal Feedback Induces Disordered Axial Hyperuniformity in an Open Colloidal Flow”** (Jianxiang Tian). This is the curated package intended for the repository cited as Ref. 37 in the manuscript. It contains the particle engines, analysis programs, compact numerical tables, and final-coordinate snapshots needed to inspect the reported plots. It is not a dump of the author's working directory.

## Start here

Python 3.10+, a C++17 compiler (`g++`), and the packages in `requirements.txt` are recommended. This release was checked with Python 3.12, NumPy 2.5.3, SciPy 1.18.1, and Matplotlib 3.11.1. The particle engines use the standard C++ library; the analysis and plotting programs use NumPy, SciPy, and Matplotlib.

```bash
python -m pip install -r requirements.txt
python smoke_test.py
python plot_paper_figures.py
```

`smoke_test.py` compiles the final particle engine in a temporary directory, runs its force self-test and a short open-channel trajectory, and checks the two particle-balance diagnostics. It does **not** validate the asymptotic hyperuniformity claim. `plot_paper_figures.py` uses the **included processed tables and snapshots** to regenerate Figs. 1–4 and S1–S4 in `prl_manuscript/figures/v10/`; it does not launch long particle simulations. The exact Word layout of a published figure can differ slightly from the standalone PDF/PNG plots.

To verify file integrity, run `python verify_checksums.py`. `MANIFEST.sha256` covers the included files other than the manifest itself.

## What is included

| Path | Purpose |
| --- | --- |
| `axial_dhu_sim/open_v2/` | Original open-channel soft-repulsive Brownian particle engine, explicit reservoirs, remote insertion/deletion baths, baseline and long-record drivers, and open-run analysis. |
| `axial_dhu_sim/open_size_scan/` | The engine and driver for the initial 128, 256, and 512 μm length scan. |
| `axial_dhu_sim/extended_scan/` | Final extended engine, length-scan driver, Hann/rectangular-window analysis, and temporal-block diagnostics. |
| `axial_dhu_sim/evidence_completion/` | Independent periodic controls and analysis of open-window counts, amplitude, and dynamical checks. |
| `axial_dhu_sim/step_size_validation/` | Matched-duration half-step control and analysis. |
| `prl_manuscript/data/` | Compact CSV/JSON values used for the plots and 27 archived final-coordinate snapshots for the spatial-order checks. |
| `prl_manuscript/make_figures.py`, `analyze_2d_order.py`, `analyze_axial_order.py` | Plot generation from the packaged tables/snapshots; their labels match the manuscript's (L_{\mathrm w}) window-length notation. |

The three C++ engines are **historical source versions used at successive simulation stages**; keeping all three makes provenance explicit. Their internal variable `O` means the observation-window length called (L_{\mathrm w}) in the revised manuscript. The code has not been renamed retroactively because that would obscure the source used for the archived runs.

Spectral amplitudes in the paper are **connected, time-averaged window estimators**; a single snapshot power in Fig. S4 is instead a periodicity diagnostic. These quantities should not be interchanged.

## Recomputing from particle trajectories

The long-run binary trajectories are **not** included. They are large and can be regenerated by the source programs, but the full nine-length, three-seed study takes substantial CPU time. The included processed tables allow immediate independent inspection and replotting, while exact re-analysis from raw trajectories requires rerunning the simulations. We do not represent the compact archive as a complete raw-trajectory deposit or as a bit-for-bit cross-platform reproducibility guarantee.

The original drivers retain their run settings and relative directory structure. In outline: run `open_v2/run_suite.py` and `extend_sampling.py`; run `open_size_scan/run_scan.py`; compile `extended_scan/engine.cpp` as `extended_scan/engine.exe` (the historical Python drivers expect that filename), then run `extended_scan/run_particles.py` for lengths 384, 640, 768, 1024, 2048, and 4096 μm. Run `extended_scan/analyze.py` and `temporal_check.py`; finally run `evidence_completion/run_controls.py` and `analyze_evidence.py`. The matched-step scripts in `step_size_validation/` use the long open-v2 baseline and expect `open_v2/engine.exe`. On Linux/macOS, an executable named `engine.exe` is still valid. Each run driver writes to its own `results/` directory. **Do not start this full sequence merely to check that the package works; use the smoke test and bundled plots first.**

Default dimensions are in μm, times in s, and energies in (k_{\mathrm B}T). The main length series uses seeds 31, 62, and 93. A central observation window of length (L_{\mathrm w}=L_c/2) is projected onto the flow direction; the paper distinguishes connected Hann/rectangular spectra from raw count-window statistics and from the fluctuating channel population. See the manuscript and Supplemental Material for definitions and limitations.

## Scope and interpretation

The model has a prescribed uniform drift, soft short-range pair repulsion, Brownian noise, finite distant particle baths, and a nonlocal density-feedback controller. It does not solve fluid hydrodynamics or pressure-driven flow. The observed low-wave-number power and disorder diagnostics are finite-range numerical evidence, not a proof of every infinite-system limit or the absence of all possible long-range order.
